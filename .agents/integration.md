# 外部系统对接规范

**加载时机**：调第三方 API / SDK、对接上游服务的 JSON 契约、处理 HTTP 响应与签名、解析外部返回的时间戳与金额。
**边界**：本模块管「跟别人家的接口打交道」；自己写接口给别人调用，看 `lang-*.md` 与 `release-*`。

## 1. 响应判定

- **【红线】HTTP 200 不代表成功**。外部系统把业务错误塞在 200 的响应体里是常态（登录失败、权限不足、对象不存在都可能返回 200）。必须按**响应体里的业务字段**判定，不能用状态码代替。
- **【默认】错误判定只看一个稳定信号**：能拿到 token 就看 token 是否为空，能拿到 id 就看 id 是否存在。不要多个字段混着判断，否则改版就失效。
- **【默认】失败原因必须透出**：上游返回的错误码、错误消息原样带到日志与抛出的异常里。只记"登录失败"等于没记。
- **【红线】显式声明 `Accept` 与 `Content-Type`**。不写时服务端可能返回 XML / 表单 / 默认格式，JSON 解析静默拿到空值。
- **【默认】第三方返回体先落一条 debug 日志**（脱敏后），排障时能直接看到原始报文。

## 2. 请求构造

- **【红线】签名类接口的参数不要二次编码**。签名基于原文计算，URL 编码会改变待签名串，结果就是 403 且看不出原因。
- **【红线】字段类型必须与上游契约一致**。上游要数值就给数值，不要用 `String` 兜住一切——序列化后会变成 `"123"`，对方校验失败，而本地类型检查完全通过。
- **【默认】超出安全范围的大整数用字符串承载**：SCN、雪花 ID、纳秒时间戳、19 位以上数字。JSON 数字在 JS/部分解析器里会丢精度。
- **【默认】外部字段有长度上限时主动截断并记日志**，不要等对方返回校验错误——那种错误信息通常不含字段名。
- **【默认】可选参数不要传空字符串占位**，按"不传"处理；空字符串与缺省在很多系统里语义不同。

## 3. 数据语义

- **【红线】时间戳先归一化再比较**。同一个字段在不同接口可能是秒、毫秒、微秒，甚至是字符串日期。统一到一种单位再运算，判据可以用量级（>1e12 视为毫秒）。
- **【默认】时间段的两端必须同源**：开始时间来自用户输入、结束时间来自接口返回时，先各自归一化，否则时间范围会错到不可解释。
- **【默认】枚举值不要硬编码字面量**，收成枚举并集中一处映射；上游新增取值时只改一个地方。
- **【默认】金额/比率用 `BigDecimal`/`Decimal`**，不用 double。

## 4. 空值与类型兜底

- **【默认】可选数值字段在 getter 兜底默认值**，但要显式注释"缺失在此场景是合法的"。典型：文件类对象没有"实例 ID"这个概念。
- **【红线】必填字段保持 fail-fast**，不要全局兜底。全局兜底会把"上游漏传"变成"静默用 0 跑完全流程"，最后在别的地方炸。
- **【默认】拆箱前判空**：`Long`/`Integer` 直接赋给 `long`/`int` 是 NPE 高发点，尤其是"以前是 int、后来改 Long"的字段。
- **【默认】集合返回 null 时按空集合处理**，但要记一条日志——正常的服务端不该返回 null。

## 5. 连接与状态

- **【红线】握手成功 ≠ 连接可用**。能连上、能发第一帧，不代表业务通道正常（重复 client_id、鉴权过期、半开连接都是先成功后失效）。判据：**有请求没有回包**就视为不可用，关闭连接、让在途请求快速失败、按退避重连。
- **【默认】断线期间的上报要缓冲**。不能靠"重试到成功"——重试次数耗尽后数据就永久丢了。
- **【默认】连接状态机要能区分"迟到的旧会话"**：旧连接回来时只关闭它自己，不能影响当前健康连接与在途请求。
- **【默认】重连退避不要在握手成功时清零**。握手成功只是必要条件，等第一条业务回包成功再清零。
- **【默认】同步异常不能逃出调度任务**（定时重连、心跳线程），否则重连链路静默中断，看起来"进程还活着但什么都不做"。

## 6. 第三方 SDK

- **【红线】有状态的 SDK 客户端不要跨线程共享，每次 new**。若 SDK 内部用实例字段存 headers / cookie / session，共享就是数据竞争——表现为签名错乱、偶发 `ConcurrentModificationException`、请求互相覆盖。
- **【红线】不要假设 SDK 会清理自己的临时状态**。真实案例：某 SDK 的登录方法把 `ACCESS-KEY` 写进复用的 `Client.headers`，登录成功后却按 token 签名，导致"每 N 分钟偶发一次签名校验失败"。用之前先读它怎么写 header。
- **【默认】封装一层自己的客户端接口**，业务代码不直接调 SDK。换版本、加拦截、修上述问题时只改一层。
- **【默认】SDK 升级单独提交**，附上"为什么不升会出问题"，不要和业务改动混在一起。

## 7. 路径与输入安全

- **【红线】外部传入的路径必须校验遍历**：按分隔符拆成组件逐级判断，不能只用 `contains("..")`（漏 Windows 反斜杠）。同时拒绝绝对路径与盘符。
- **【默认】文件名拼接前过滤非法字符**（`/ \ : * ? " < > |` 与控制字符），长度也要限制。
- **【默认】写到外部系统的名字要留余量**：同名字段在对方系统里可能有更短的上限。

## 8. 长任务与分布式协作

- **【默认】进度/统计要有统一分母**：多节点各自算分母必然打架。由一个节点算好写入共享通道，其他节点只上报自己的分子。
- **【红线】空队列不能当"任务结束"的判据**：它同时意味着"还没开始"。必须让生产者先写"我已入队完成"的标记，消费者看到标记才收尾（完成屏障）。
- **【默认】缓存要有"未就绪"语义**：缓存的哨兵值（-1、null、空集合）不能被当成真实数据参与判断，否则会得出"任务空闲"这类假结论。
- **【默认】强相关的两个状态合并成单 key 原子写**，读侧对旧格式做只读兼容。两个 key 分开写，进程被杀时会留下撕裂状态。
- **【默认】池化前先搞清 `close()` 的真实语义**：它可能不是"释放资源"，而是"等待队列排空"的屏障。删掉它等于删掉同步点，要用等价等待替代。
- **【默认】长任务用"无进展超时"，不用总时长上限**：判据要选能反映真实进展的信号（行级/条级计数），只数"分片完成数"会把大分片误杀。

## 9. 批量写入与类型映射

- **【红线】写操作失败必须能从返回值看见**。异步/后台刷写会吞掉行级错误，调用方以为成功。校验每次响应（`hasRowError()` 之类）与最终 flush 结果。
- **【默认】性能不够时用"手动刷写按批 + 逐批校验"**，而不是退回后台异步。前者慢一点但错得看得见，后者快但会静默丢数据。
- **【默认】类型映射用专用 API**：十进制用 decimal 接口、变长字符串用 varchar 接口、日期用 date 接口，不要拿通用二进制再自己解——通用接口在特殊类型上会直接抛异常。
- **【默认】拷贝二进制按 `remaining()`**，不要用 `array()`：后者返回整个底层数组，忽略 position/limit，会拷出多余或错位字节。
- **【建议】批量大小、块大小、刷写粒度这类旋钮外置成配置**，带边界校验与默认值注释，压测时能直接调小。

## 10. 反例

```java
// ✗ 用状态码判断登录成功
if (resp.getStatusCode() == 200) { token = parse(resp); }   // 200 但 token 为 null

// ✓ 用业务字段判断，失败原因带出来
LoginRes res = parse(resp);
if (!res.ok()) throw new AuthException("login rejected: " + res.reason());

// ✗ 类型宽松导致契约不一致
class DumpParam { String clientId; }        // 上游要求数值 → 下发后被拒
class DumpParam { Long clientId; }

// ✗ 共享 SDK 实例
private final Auth auth = Auth.ak(...);     // 多线程并发 put header → 签名错乱

// ✗ 时间戳直接用
long to = api.getEndTime();                 // 毫秒
long from = req.getStartTime();             // 秒
if (from > to) { ... }                      // 永远成立
```
