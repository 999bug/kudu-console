# Vue 规范

**加载时机**：检测到 `package.json` 含 `vue`，或 `vite.config.*` + `src/App.vue`，或要新增、修改前端页面。

## 1. 版本与写法

- **【默认】Vue 3 用组合式 API + `<script setup>`**。新文件不要写 Options API（`data()` / `methods`）；老文件改造时保持一致，不要一个文件两种写法。
- **【默认】TypeScript 项目必须给 props / emits / 接口响应加类型**；JS 项目至少用 JSDoc 或清晰的命名代替 `any` 满天飞。
- **【默认】单文件组件顺序**：`<script setup>` → `<template>` → `<style scoped>`。
- **【红线】不擅自引入 UI 组件库、图标库、CSS 框架、CDN 资源**。内网项目引 CDN 会直接打不开；要引先问，说明体积与收益。

## 2. 状态管理

- **【默认】状态就近**：组件内 `ref` / `reactive` 优先，父子 `props` + `emit`，只有跨页面/跨层级共享才上 store（Pinia）。
- **【默认】computed 能推出来的一律用 computed**，不要用 `watch` 手动同步两份状态——那是重复状态的源头。
- **【红线】不直接改 props**，用 `defineModel()` 或 `emit('update:xxx')`。
- **【默认】store 里不放组件实例、DOM 引用、大对象数组**；列表数据放在使用它的页面，按需取。
- **【默认】派生数据不进 store**（能用 getter 算的不要存）。

## 3. 请求与错误

- **【默认】请求统一走一个 api 层**（`src/api.js` 或 `src/api/*`），组件里不拼 URL、不写 `fetch` 细节。
- **【默认】统一处理非 2xx**：读响应里的 `code` / `message` 展示，不要把整个响应对象丢进 `alert`。
- **【红线】禁止空 catch**：`catch (e) {}` 会让界面停在"加载中"永远不动。
- **【默认】加载态与空态都要有**：`loading` / `error` / `empty` 三态明确，只在 `loading` 显示骨架，不要用"空白页"当加载态。
- **【默认】接口变了同步改前端调用与文档**，不留"字段暂时没有"的兼容层。

## 4. 模板与样式

- **【红线】`v-for` 必须带 `:key`**，且用稳定 id，不用数组下标（下标在增删时会复用错节点）。
- **【默认】模板里不写复杂表达式**，超过一个三元或一次函数调用就提到 computed。
- **【默认】样式用 `scoped`**；全局样式只在 `styles.css` 里定义，不在组件里写全局选择器。
- **【红线】不用 `!important` 堆叠解决覆盖问题**，先查选择器优先级与样式加载顺序。
- **【默认】长文本容器一律 `ellipsis + title`**，窄屏不要靠换行硬撑布局。
- **【建议】沿用项目既有视觉风格**（纯色、无渐变、无装饰性 emoji），不要混入第二种设计语言。

## 5. 路由与构建

- **【默认】路由按页面懒加载**（`() => import('./views/X.vue')`），首屏只加载必要代码。
- **【红线】新增路由必须同步 SPA 回退配置**（服务端 `index.html` 兜底 / Pages 的 `404.html`），否则直接访问该路径 404。这类问题只有刷新时才暴露，测试时容易漏。
- **【默认】构建产物不入库**（`dist/`、后端 `static/` 目录加进 `.gitignore`），由 CI 或构建脚本生成。
- **【默认】`base` 与部署路径一致**：部署在子路径（`/repo/`）时必须改 `base`，否则白屏 + 资源 404。
- **【红线】不把 token、内网地址、调试开关写进前端代码**：构建产物里的任何变量都是公开的。

## 6. 可访问性与交互

- **【默认】可点击的用 `<button>` / `<a>`**，不用 `<div @click>`（键盘不可达、无焦点样式）。
- **【默认】表单控件配 `<label>`**，图标按钮加 `aria-label`。
- **【默认】异步操作期间禁用触发按钮**，防重复提交；危险操作二次确认并要用户手输名称。
- **【建议】列表超过 200 行考虑虚拟滚动**，不要靠 `v-if` 硬扛。

## 7. 验证（前端改动必做）

只看 `npm run build` 通过不算验证。至少：

1. 起本地服务，实际点一遍主路径（不是只看代码）。
2. 在窄屏与宽屏各截一次图，确认无溢出、无错位、无被裁剪的按钮。默认 `1440 / 768 / 375`，或按 profile 指定的断点。
3. 新增路由：直接访问该 URL 并刷新，确认不 404。
4. 改接口交互：验证成功、失败、空数据三种状态。

## 8. 反例清单（见到就改）

```vue
<!-- ✗ 用下标当 key -->
<li v-for="(row, i) in rows" :key="i">

<!-- ✗ 直接改 props -->
props.value = newValue

<!-- ✗ 用 watch 同步两份状态 -->
watch(() => a.value, (v) => { b.value = v })

<!-- ✗ 空 catch，界面永远转圈 -->
try { await save() } catch (e) {}

<!-- ✗ div 当按钮 -->
<div class="btn" @click="submit">保存</div>
```
